# Feature Specification: Trading Wizard Web

**Feature Branch**: `004-trading-wizard-web`
**Created**: 2026-01-05
**Status**: Clarified
**Input**: User description: "trading_wizard_web/README.md 의 내용대로 사용자 계정별 거래 데이터 입력, 이력 관리, 백테스트, 시각화를 수행하는 웹 애플리케이션 개발"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - PEM 키 기반 인증 (Priority: P1)

개인 투자자가 Trading Wizard Web에 접속하여 PEM 개인키 파일로 인증한다. 개인정보(이메일, 비밀번호 등)를 수집하지 않고, 암호화 키 쌍으로만 사용자를 식별한다.

**Why this priority**: 모든 기능의 기반이 되는 사용자 인증 시스템. 개인정보 없이 계정별 데이터 분리가 핵심 요구사항.

**Independent Test**: 키 생성 → PEM 파일로 로그인 → 대시보드 접근까지 완료되면 독립적으로 검증 가능

**Acceptance Scenarios**:

1. **Given** 신규 사용자가 접속, **When** "새 키 생성" 버튼 클릭, **Then** 공개키/개인키 쌍이 생성되고 개인키(PEM 파일)가 다운로드됨
2. **Given** PEM 파일을 보유한 사용자가 로그인 페이지에 접속, **When** PEM 파일을 업로드(또는 드래그앤드롭), **Then** 서명 검증 후 대시보드 페이지로 이동
3. **Given** 로그인된 사용자, **When** 로그아웃 버튼 클릭, **Then** 세션이 종료되고 로그인 페이지로 이동
4. **Given** 잘못된 PEM 파일 업로드, **When** 로그인 시도, **Then** "유효하지 않은 키 파일" 오류 메시지 표시

---

### User Story 2 - 거래 데이터 입력 (Priority: P1)

투자자가 실제 체결된 매수/매도 거래를 시스템에 입력한다. 종목코드, 거래유형(매수/매도), 수량, 단가, 거래일자를 입력하면 포트폴리오에 반영된다.

**Why this priority**: 거래 데이터 입력은 이력 관리와 시각화의 기반 데이터를 생성하는 핵심 기능

**Independent Test**: 거래 입력 후 포트폴리오에 해당 종목이 반영되는지 확인

**Acceptance Scenarios**:

1. **Given** 로그인한 사용자가 거래입력 페이지에 접속, **When** 종목코드(005930), 매수, 10주, 71,200원, 2026-01-05 입력 후 저장, **Then** 포트폴리오에 삼성전자 10주가 추가됨
2. **Given** 삼성전자 10주를 보유한 사용자, **When** 종목코드(005930), 매도, 5주, 72,000원 입력 후 저장, **Then** 포트폴리오에 삼성전자 5주로 변경되고 실현손익이 계산됨
3. **Given** 거래입력 페이지, **When** 잘못된 종목코드 입력, **Then** 유효하지 않은 종목코드라는 오류 메시지 표시

---

### User Story 3 - 포트폴리오 대시보드 시각화 (Priority: P2)

투자자가 현재 보유 종목, 평가손익, 총 자산을 한 화면에서 확인한다. 각 종목별 수익률과 전체 포트폴리오 수익률을 시각적으로 파악할 수 있다.

**Why this priority**: 핵심 가치 제공 기능. 입력된 데이터를 의미있는 정보로 변환하여 투자 의사결정 지원

**Independent Test**: 보유 종목과 손익 정보가 대시보드에 올바르게 표시되는지 확인

**Acceptance Scenarios**:

1. **Given** 3개 종목을 보유한 사용자가 대시보드 접속, **When** 페이지 로드 완료, **Then** 초기자본, 총 평가액, 현금잔고, 보유종목 수가 요약 카드에 표시됨
2. **Given** 대시보드 페이지, **When** 보유종목 섹션 확인, **Then** 각 종목별 종목코드, 종목명, 수량, 매수가, 현재가, 평가손익, 수익률이 테이블에 표시됨
3. **Given** 대시보드 페이지, **When** 손익현황 섹션 확인, **Then** 미실현 손익, 실현 손익, 총 거래수가 표시됨

---

### User Story 4 - 거래 이력 관리 (Priority: P2)

투자자가 과거에 입력한 모든 거래 내역을 조회하고 관리한다. 날짜별, 종목별로 필터링하여 거래 이력을 검토할 수 있다.

**Why this priority**: 거래 추적 및 세금 신고, 투자 분석에 필수적인 기능

**Independent Test**: 거래 이력 페이지에서 과거 입력한 모든 거래가 표시되는지 확인

**Acceptance Scenarios**:

1. **Given** 10건의 거래를 입력한 사용자가 거래이력 페이지 접속, **When** 페이지 로드 완료, **Then** 최근 거래부터 시간순으로 10건 모두 표시됨
2. **Given** 거래이력 페이지, **When** 특정 종목코드로 필터링, **Then** 해당 종목의 거래만 표시됨
3. **Given** 거래이력 페이지, **When** 날짜 범위 지정(2025-01-01 ~ 2025-12-31), **Then** 해당 기간의 거래만 표시됨
4. **Given** 잘못 입력한 거래 선택, **When** 삭제 버튼 클릭 후 확인, **Then** 해당 거래가 삭제되고 포트폴리오에 반영됨

---

### User Story 5 - 백테스트 실행 및 결과 조회 (Priority: P3)

투자자가 특정 기간과 종목 리스트를 지정하여 볼린저 밴드 스퀴즈 전략의 백테스트를 실행하고 결과를 확인한다.

**Why this priority**: 고급 기능으로, 기본 거래 관리 기능이 완성된 후 추가 가치 제공

**Independent Test**: 백테스트 파라미터 입력 후 결과가 생성되고 조회 가능한지 확인

**Acceptance Scenarios**:

1. **Given** 백테스트 페이지 접속, **When** 연도(2023), 종목리스트(KOSPI Top 100), 초기자본(1,000,000원) 입력 후 실행 클릭, **Then** 백테스트가 실행되고 진행 상태가 표시됨
2. **Given** 백테스트 실행 완료, **When** 결과 페이지 확인, **Then** 총 수익률, 최대 낙폭, 거래수, 승률이 표시됨
3. **Given** 백테스트 결과 페이지, **When** 상세보기 클릭, **Then** 월별 수익률, 거래 내역, 자산 추이 차트가 표시됨
4. **Given** 이전에 실행한 백테스트 결과, **When** 저장된 결과 목록 조회, **Then** 과거 백테스트 결과를 불러올 수 있음

---

### User Story 6 - 전략 설정 관리 (Priority: P3)

투자자가 자신의 투자 전략 파라미터(최대 포지션 수, 손절선, 신뢰도 임계값 등)를 설정하고 저장한다.

**Why this priority**: 개인화 기능으로, 핵심 기능 완료 후 사용자 맞춤 설정 제공

**Independent Test**: 설정 변경 후 저장되고, 다음 로그인 시에도 유지되는지 확인

**Acceptance Scenarios**:

1. **Given** 설정 페이지 접속, **When** 최대 포지션을 15개에서 10개로 변경 후 저장, **Then** 변경사항이 저장되고 확인 메시지 표시
2. **Given** 설정 저장 후 로그아웃, **When** 다시 로그인하여 설정 페이지 확인, **Then** 변경된 설정값(10개)이 유지됨
3. **Given** 설정 페이지, **When** 손절선을 -5%에서 -3%로 변경, **Then** 향후 매매 신호 계산에 새 손절선 적용

---

### Edge Cases

- PEM 파일 분실 시 복구 불가 → 새 키 생성 필요 (기존 데이터 접근 불가, 신규 사용자로 시작)
- 동일 종목을 같은 날 여러 번 거래한 경우 각각 별도 거래로 기록
- 보유 수량보다 많은 매도 시도 시 오류 메시지 표시 및 입력 차단
- 백테스트 실행 중 페이지 이탈 시 백그라운드에서 계속 실행하고 완료 후 알림
- 세션 만료 시 자동 로그아웃 후 로그인 페이지로 리다이렉트
- 종목코드 입력 시 자동완성으로 종목명 제안
- 잘못된 형식의 PEM 파일 업로드 시 명확한 오류 메시지 표시

## Requirements *(mandatory)*

### Functional Requirements

**사용자 인증 (PEM 키 기반, 개인정보 미수집)**
- **FR-001**: System MUST 공개키/개인키 쌍 생성 기능 제공 (브라우저 내 생성, 개인키는 사용자만 보유)
- **FR-002**: System MUST PEM 파일 업로드를 통한 서명 기반 인증 제공
- **FR-003**: System MUST 로그인 세션을 유지하고 자동 로그아웃(30분 미활동) 처리
- **FR-004**: System MUST 공개키 핑거프린트를 사용자 식별자로 사용 (개인정보 불필요)

**거래 데이터 관리**
- **FR-005**: System MUST 거래 입력 시 종목코드 유효성 검증 (KOSPI/KOSDAQ 상장 종목)
- **FR-006**: System MUST 매수 거래 시 잔고 확인 및 부족 시 경고
- **FR-007**: System MUST 매도 거래 시 보유 수량 확인 및 초과 시 차단
- **FR-008**: System MUST 거래 입력 후 포트폴리오 자동 업데이트

**포트폴리오 관리**
- **FR-009**: System MUST 보유 종목의 현재가를 주기적으로 갱신 (장중 최소 15분 간격)
- **FR-010**: System MUST 종목별/전체 평가손익 및 수익률 계산
- **FR-011**: System MUST 초기자본 설정 기능 제공

**거래 이력**
- **FR-012**: System MUST 모든 거래 이력을 영구 보관
- **FR-013**: Users MUST be able to 거래 이력 검색 (날짜, 종목, 거래유형)
- **FR-014**: Users MUST be able to 거래 이력 내보내기 (CSV 형식)

**백테스트**
- **FR-015**: System MUST trading_wizard_bundle의 볼린저 밴드 스퀴즈 전략 백테스트 실행
- **FR-016**: System MUST 백테스트 결과 저장 및 조회 기능 제공
- **FR-017**: System MUST 백테스트 파라미터 설정 (기간, 종목리스트, 초기자본)

**설정**
- **FR-018**: System MUST 사용자별 전략 파라미터 저장 (최대 포지션, 손절선, 신뢰도 임계값)
- **FR-019**: System MUST 닉네임 설정 기능 제공 (선택사항, 표시용)

### Key Entities

- **User**: 시스템 사용자. 공개키, 공개키 핑거프린트(사용자 ID), 닉네임(선택), 가입일 보유. 개인정보 미수집
- **Portfolio**: 사용자의 포트폴리오. 초기자본, 현금잔고, 생성일 포함. User와 1:1 관계
- **Position**: 보유 종목. 종목코드, 종목명, 수량, 평균매수가, 매수일. Portfolio와 N:1 관계
- **Trade**: 개별 거래. 거래일, 종목코드, 거래유형(매수/매도), 수량, 단가, 실현손익. Portfolio와 N:1 관계
- **BacktestResult**: 백테스트 결과. 파라미터, 수익률, MDD, 거래수, 승률, 실행일. User와 N:1 관계
- **UserSettings**: 사용자 전략 설정. 최대 포지션, 손절선, 신뢰도 임계값, 포지션당 비중. User와 1:1 관계

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 계정 생성부터 첫 거래 입력까지 5분 이내 완료 가능
- **SC-002**: 대시보드 로딩 시 3초 이내에 모든 포트폴리오 정보 표시
- **SC-003**: 50개 이상의 거래 이력을 2초 이내에 조회 가능
- **SC-004**: 백테스트 결과(1년, 100종목)가 3분 이내에 생성
- **SC-005**: 동시 접속 100명의 사용자 지원 (응답 지연 없이)
- **SC-006**: 90% 이상의 사용자가 도움말 없이 거래 입력 완료
- **SC-007**: 모바일 기기에서도 주요 기능(대시보드, 거래입력) 사용 가능

## Clarifications

### Session 2026-01-05

- Q: PEM 키 생성에 사용할 암호화 알고리즘은? → A: ECDSA P-256 (작은 키 크기, 브라우저 호환성 우수)
- Q: 사용자 데이터 저장소는? → A: SQLite (파일 기반, 배포 간단)

## Assumptions

- **인증 방식**: PEM 개인키 파일 기반 인증 (ECDSA P-256 알고리즘). 서버는 공개키만 저장하고 개인키는 사용자만 보유
- **개인정보**: 이메일, 비밀번호, 전화번호 등 개인정보를 수집하지 않음
- **키 분실**: PEM 파일 분실 시 계정 복구 불가 (사용자 책임으로 안내)
- 종목 현재가 데이터는 외부 API(Yahoo Finance 등)에서 조회하며, 실시간이 아닌 15분 지연 데이터 사용
- 백테스트는 기존 trading_wizard_bundle의 로직을 재사용
- 한국어 UI 기본 제공, 다국어 지원은 향후 확장
- 개인 투자자 대상 서비스로, 기관 투자자 기능(대량 주문, 다중 계정 관리 등)은 범위 외
- 모든 금액은 KRW 단위로 표시
